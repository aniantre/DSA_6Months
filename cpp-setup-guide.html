Install GCC via MSYS2 (the right way on Windows)
MSYS2 gives you a proper Unix-like toolchain including GCC, g++, and make. Much better than old MinGW.
~8 min
Why MSYS2? Old "MinGW" is outdated and broken on Windows 11. MSYS2 ships the latest GCC and handles PATH correctly. This is what competitive programmers use.
Download + Install
  • Go to msys2.org → download the installer (msys2-x86_64-*.exe) → run it
  • Install to C:\msys64 (default) — keep this path, we'll reference it
  • After install, it opens an MSYS2 terminal. Run the update command below.
MSYS2 Terminal
BASH
# Step 1: Update MSYS2 package database $ pacman -Syu # It may close the terminal. Reopen MSYS2 and run: $ pacman -Su # Step 2: Install GCC (g++ for C++) $ pacman -S --needed base-devel mingw-w64-ucrt-x86_64-toolchain # Press Enter when asked to select packages (install all) # Type Y when asked to confirm # Step 3: Verify installation $ g++ --version g++ (Rev1, Built by MSYS2 project) 13.x.x
Add GCC to Windows PATH
  • Press Win + S → search "Environment Variables" → open it
  • Under "System variables" → find Path → click Edit
  • Click New → paste: C:\msys64\ucrt64\bin
  • Click OK → OK → OK
  • Open a new Command Prompt and verify:
Command Prompt (new window)
CMD
C:\> g++ --version g++ (Rev1, Built by MSYS2 project) 13.x.x 20231008 C:\> gdb --version GNU gdb (GDB) 14.x
✓ Both commands must work. If g++ works but gdb doesn't, the PATH is correct — gdb ships with the toolchain and will work after reopening VSCode.

Configure Build Tasks + Debugger + Settings
This is the key step. After this, Ctrl+Shift+B compiles and runs your file in one shot.
~8 min
How to create these files: In your DSA folder, create a folder called .vscode. Inside it, create three files: tasks.json, launch.json, settings.json. Paste the contents below.
File 1 of 3 — .vscode/tasks.json — (Build + Run with Ctrl+Shift+B)
.vscode/tasks.json
JSON
{ "version": "2.0.0", "tasks": [ { "label": "Build and Run C++ (DSA)", "type": "shell", "command": "g++", "args": [ "-std=c++17", // C++17 standard "-O2", // optimization (same as LeetCode) "-Wall", // show all warnings "-Wextra", // extra warnings "-fsanitize=address,undefined", // catch memory bugs + UB "-g", // debug info "${file}", // current open file "-o", "${fileDirname}/${fileBasenameNoExtension}.exe" ], "group": { "kind": "build", "isDefault": true // Ctrl+Shift+B triggers this }, "presentation": { "reveal": "always", "panel": "shared", "clear": true }, "problemMatcher": "$gcc" }, { "label": "Compile Only (no run)", "type": "shell", "command": "g++", "args": [ "-std=c++17", "-Wall", "-g", "${file}", "-o", "${fileDirname}/${fileBasenameNoExtension}.exe" ], "group": "build", "problemMatcher": "$gcc" } ] }
-fsanitize=address,undefined is gold for DSA. It catches: out-of-bounds array access, use after free, integer overflow, null pointer dereference — all bugs that silently pass on LeetCode but crash your logic. Remove it only if compile time feels slow.
File 2 of 3 — .vscode/launch.json — (F5 to Debug)
.vscode/launch.json
JSON
{ "version": "0.2.0", "configurations": [ { "name": "Debug Current File", "type": "cppdbg", "request": "launch", "program": "${fileDirname}/${fileBasenameNoExtension}.exe", "args": [], "stopAtEntry": false, "cwd": "${fileDirname}", "environment": [], "externalConsole": false, // use VSCode terminal "MIMode": "gdb", "miDebuggerPath": "C:/msys64/ucrt64/bin/gdb.exe", "preLaunchTask": "Compile Only (no run)", "setupCommands": [ { "description": "Pretty print", "text": "-enable-pretty-printing", "ignoreFailures": true } ] } ] }

Your DSA Problem Template
Copy this for every new problem. Contains all STL includes, fast I/O, and handy macros used in DSA.
~2 min
How to use: Copy template.cpp → rename to problem_name.cpp → write your solution in the solve() function → test cases go in main().
month1/template.cpp — copy this for every problem
C++17
// ───────────────────────────────────────────────────────────────────────── // Problem: [PROBLEM NAME HERE] // Link: https://leetcode.com/problems/... // Pattern: [e.g. Two Pointers / Sliding Window / DP - Knapsack] // Time: O(?) Space: O(?) // ───────────────────────────────────────────────────────────────────────── #include <bits/stdc++.h> // includes everything — fine for DSA using namespace std; // ── Type aliases (saves typing, matches competitive programming style) ── using ll = long long; using vi = vector<int>; using vll = vector<ll>; using pii = pair<int,int>; using vvii = vector<vector<int>>; // ── Constants ── const int INF = 1e9; const ll LINF = 1e18; const int MOD = 1e9 + 7; // ────────────────────────────────────────────────────────────────────────── // YOUR SOLUTION HERE // ────────────────────────────────────────────────────────────────────────── class Solution { public: // Replace with actual function signature from LeetCode int solve(vector<int>& nums) { int n = nums.size(); // your code here return 0; } }; // ────────────────────────────────────────────────────────────────────────── // TEST CASES — run locally before submitting to LeetCode // ────────────────────────────────────────────────────────────────────────── int main() { // Fast I/O (not needed for LeetCode but good habit) ios::sync_with_stdio(false); cin.tie(nullptr); Solution sol; // ── Test 1 ── { vector<int> nums = {2, 7, 11, 15}; int result = sol.solve(nums); cout << "Test 1: " << result << " (expected: ...)\n"; } // ── Test 2 — edge case ── { vector<int> nums = {}; // empty input int result = sol.solve(nums); cout << "Test 2: " << result << " (expected: ...)\n"; } // ── Test 3 — single element ── { vector<int> nums = {1}; int result = sol.solve(nums); cout << "Test 3: " << result << " (expected: ...)\n"; } return 0; }
About #include <bits/stdc++.h>: This is a GCC-specific header that includes everything. It doesn't exist on MSVC (Visual Studio), but since we're using GCC, it works fine. LeetCode also uses GCC, so it compiles on submission too. Saves you from forgetting #include <algorithm>.
Example: Two Sum solved with this template
month1/two_sum.cpp
C++17
#include <bits/stdc++.h> using namespace std; // Pattern: Seen-Before (Hash Map) // Time: O(n) Space: O(n) class Solution { public: vector<int> twoSum(vector<int>& nums, int target) { unordered_map<int,int> seen; // value → index for (int i = 0; i < (int)nums.size(); i++) { int complement = target - nums[i]; if (seen.count(complement)) return {seen[complement], i}; seen[nums[i]] = i; } return {}; } }; int main() { ios::sync_with_stdio(false); cin.tie(nullptr); Solution sol; // Test 1: [2,7,11,15] target=9 → [0,1] { vi nums = {2,7,11,15}; auto res = sol.twoSum(nums, 9); cout << "[" << res[0] << "," << res[1] << "] expected [0,1]\n"; } // Test 2: [3,2,4] target=6 → [1,2] { vi nums = {3,2,4}; auto res = sol.twoSum(nums, 6); cout << "[" << res[0] << "," << res[1] << "] expected [1,2]\n"; } return 0; }
6
Your Daily Compile + Run Workflow
How to go from blank file to tested solution in your 1-hour sessions.
Learn once
1️⃣
Open a new problem
Copy template.cpp → rename to problem_name.cpp. Fill in the header comment: problem name, link, pattern you're using.
2️⃣
Write solution in class
Implement inside the Solution class — same structure as LeetCode. Paste the function signature directly from LeetCode.
3️⃣
Add test cases in main()
LeetCode's examples go here first. Always add an edge case: empty input, single element, all same values, negatives.
4️⃣
Compile + Run
Ctrl+Shift+B → compiles and shows output in terminal. Errors appear inline in your code (with Error Lens). Fix → Ctrl+Shift+B → repeat.
5️⃣
All tests pass locally
Copy ONLY the Solution class to LeetCode. Never copy the #include or main(). LeetCode has its own main. Submit.
6️⃣
If WA or TLE on LeetCode
Add the failing test case to your local main(). Debug locally with F5 — step through with the debugger. Much faster than LeetCode's debugger.

Testing with stdin input (for problems with cin)
Reading from cin in main() — for competitive style
C++17
int main() { ios::sync_with_stdio(false); cin.tie(nullptr); // Read array from stdin int n; cin >> n; vi nums(n); for (auto& x : nums) cin >> x; Solution sol; auto result = sol.twoSum(nums, 9); for (auto x : result) cout << x << " "; cout << "\n"; return 0; } // Then create input.txt: // 4 // 2 7 11 15 // Run: two_sum.exe < input.txt

Troubleshooting
'g++' is not recognized → PATH not set. Close all terminals, reopen VSCode, try again. If still broken: Win+S → Environment Variables → verify C:\msys64\ucrt64\bin is in System Path.
Compiler errors shown in terminal but not in code → Install the "Error Lens" extension. Also check that C_Cpp.errorSquiggles is "enabled" in settings.json.
Debugger doesn't stop at breakpoints → Make sure you compiled with -g flag (it's in our tasks.json). Also check miDebuggerPath in launch.json points to your actual gdb.exe path.
-fsanitize causes "cannot find -lasan" → Remove -fsanitize=address,undefined from tasks.json. Some Windows + GCC combos don't support sanitizers. The code still compiles fine without it.
bits/stdc++.h not found → This means you're using MSVC (Visual Studio compiler) not GCC. Check that your PATH has MSYS2's GCC, not VS's cl.exe. Run where g++ in terminal — it should point to C:\msys64\ucrt64\bin\g++.exe.
